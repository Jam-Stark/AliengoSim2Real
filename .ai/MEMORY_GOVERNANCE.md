# Active, candidate-triggered memory governance

Do not append merely because an entry exists. Create, move, split, merge, supersede or retire when that improves retrieval and current-truth accuracy.

Memory curation is not a closure stage. It starts only when a durable candidate exists.

Candidate triggers include: reusable verified fact with no route, mixed topics, repeated rediscovery, new evidence superseding old truth, stale baseline numbers, duplicate drift, or an entry that has become too costly to recover.

Workers/researchers/reviewers propose candidates. Main or a designated curator performs canonical writes. Live progress, heartbeats, P2P messages, raw logs and unsupported inference do not become memory.

Complex move/split/merge/supersede/retire operations require explicit semantic editing; helper scripts must not pretend to automate them from a label alone.
